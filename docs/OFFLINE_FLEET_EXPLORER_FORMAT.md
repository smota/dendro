# Offline Fleet Explorer JSON Format Specification

The **Offline Fleet Explorer** ([`site/viewer.html`](../site/viewer.html)) is Dendro's standalone, zero-dependency analytical inspection tool. It runs entirely client-side in browser memory without sending data to a remote server or requiring an active backend daemon.

This document specifies the JSON input format accepted by the Offline Fleet Explorer, covering supported envelope structures, field-by-field schema definitions mapped to the four explorer panels, and privacy-preserving projection invariants.

---

## 1. Overview & Quick Demo

The Offline Fleet Explorer visualizes multi-agent software engineering execution across four distinct layers:
1. **Pulse & Session Timeline (`#pulse`)**: Fleet yield, concurrency histograms, aggregate actor time allocations, and unified state transition timelines.
2. **Work Lineage & Model Accounting (`#flow`)**: Queue handoffs and rework return ribbons, model token categorization, pair friction matrix, and attributed token overhead.
3. **Actor Evidence Inspector (`#trace`)**: Per-actor aliased operational metrics, engineering vs. ceremony tool-call breakdown, container hold vs. leaf stall durations.
4. **Layer Insights & Security Posture (`#insights`)**: Standardized `insight_v1` cards across Model, Harness, Coordination, Environment, and Security domains, alongside closed-vocabulary security posture facts.

### Loading the Demo File

You can test the Offline Fleet Explorer immediately using the bundled 24-hour multi-agent sprint fixture:

1. Open [`site/viewer.html`](../site/viewer.html) in any modern web browser.
2. Click **Open report / trace JSON** in the toolbar.
3. Select [`site/fixtures/fleet-explorer-demo.json`](../site/fixtures/fleet-explorer-demo.json) (or [`docs/assets/fleet-explorer-demo.json`](assets/fleet-explorer-demo.json)).
4. The explorer immediately parses and projects the data across all four tabs without network traffic.

### Generating Analytical Exports via Dendro CLI

You can generate compatible JSON export envelopes directly from a running Dendro instance:

```bash
# Generate a full fleet decisions report envelope
dendro report decisions --window 7d > report.json

# Generate a targeted forensic trace envelope
dendro trace --metric-id handoff_friction --window 7d > trace.json
```

Both files can be dragged or loaded directly into [`site/viewer.html`](../site/viewer.html).

## 2. Supported Envelope Shapes

The Offline Fleet Explorer accepts two primary top-level JSON structures. In both cases, only numeric metrics, timestamped arrays, and closed-vocabulary enumerations are admitted.

### Shape A: Report Envelope (`payload.product = "AI Fleet Intelligence"`)

Generated by `dendro report ...`. The explorer unwraps `payload`:

```json
{
  "definition_version": "report-v1",
  "metric": "fleet_intelligence",
  "payload": {
    "product": "AI Fleet Intelligence",
    "from": "2026-10-27T00:00:00Z",
    "to": "2026-10-28T00:00:00Z",
    "tokens": 482910400,
    "m1_yield": 0.785,
    "m3_rework_chains": 4,
    "m1_by_seat": [...],
    "activity": [...],
    "activity_events": [...],
    "advisory_idle_claimed": { "intervals": [...] },
    "context_compactions": { "events": [...] },
    "handoff_members": [...],
    "pair_medians": [...],
    "m2_pairs": [...],
    "ring_boundaries": { "edges": [...] },
    "token_categories": { ... },
    "task_intake_overhead": { ... },
    "fleet_concurrency": { ... },
    "insights": [...],
    "lineage": { ... },
    "environment": { ... },
    "security": { ... }
  }
}
```

*Note:* If top-level `product === "AI Fleet Intelligence"`, the root object itself is used directly as the payload.

### Shape B: Forensic Trace Envelope (`metric_id` + `inputs`)

Generated by `dendro trace ...`. The explorer unwraps `inputs`:

```json
{
  "metric_id": "handoff_friction",
  "definition_version": "trace-v1",
  "inputs": {
    "from": "2026-10-27T00:00:00Z",
    "to": "2026-10-28T00:00:00Z",
    "tokens": 12450000,
    "m1_by_seat": [...],
    "handoff_edges": [...],
    "pair_medians": [...]
  }
}
```

## 3. Complete Schema Reference by Explorer Tab

### 3.1. Tab 1: Pulse & Session Timeline (`#pulse`)

#### Top-level Summary Counters
- `from` (`string`, ISO 8601): Observation window start timestamp (e.g. `"2026-10-27T00:00:00Z"`).
- `to` (`string`, ISO 8601): Observation window end timestamp (e.g. `"2026-10-28T00:00:00Z"`).
- `tokens` (`number`): Total tokens consumed across the fleet in the window. Displayed as **Recorded tokens**.
- `m1_yield` (`number`): Ratio of tokens per nonreturned delivery (or items per million tokens). Displayed as **M1 · tokens / nonreturned delivery**.
- `m3_rework_chains` (`number`): Total count of rework cycles (`is_return: true`). Displayed as **Rework chains**.
- `fleet_concurrency.effective_parallelism` (`number`): Fleet parallel execution factor (e.g. `3.42`). Displayed as **Effective parallelism**.

#### Actor Activity Bands (`activity`)
Aggregate durations for each actor across the window. Rendered as stacked proportion bars in `#bands`:
```json
{
  "seat": "builder-backend@core-rig",
  "observed_secs": 79200,
  "active_secs": 52400,
  "idle_with_work_secs": 16800,
  "idle_without_work_secs": 7200,
  "waiting_human_secs": 1800,
  "unknown_secs": 1000,
  "unparked_container_secs": 5400,
  "leaf_stall_secs": 3200,
  "engineering_calls": 864,
  "ceremony_calls": 92,
  "observed_spans": [
    { "from": "2026-10-27T01:00:00Z", "to": "2026-10-27T12:00:00Z" },
    { "from": "2026-10-27T13:00:00Z", "to": "2026-10-28T00:00:00Z" }
  ]
}
```
- **Band Keys (`bandKeys`)**:
  - `active_secs` (green `#10b981`): Time spent executing tool calls or model inference.
  - `idle_with_work_secs` (yellow `#fbbf24`): Time spent with assigned work in queue but no execution.
  - `idle_without_work_secs` (slate `#475569`): Time spent parked with an empty queue.
  - `waiting_human_secs` (purple `#a78bfa`): Time spent blocked awaiting operator approval or input.
  - `unknown_secs` (gray `#94a3b8`): Unmeasured or unverified session intervals.
- **Container Hold Subset**: `unparked_container_secs` is rendered as a hatched pattern (`url(#container-hatch)`) subtracted directly from `idle_with_work_secs` to prevent double-counting.
- **Life Boundaries (`observed_spans`)**: List of `{ from, to }` intervals when the actor's session harness was mounted. Time outside these spans represents unobserved gaps; state is never carried across gaps.

#### Session Activity Timeline (`activity_events`, `advisory_idle_claimed`, `context_compactions`)
Renders an SVG Gantt timeline in `#timeline` with a lane per actor:
- `activity_events` (`Array<{ seat: string, ts: string, state: string }>`):
  - `state`: Must be one of `"running"` (green), `"idle"` (slate), or `"needs_input"` (purple).
  - Intervals are drawn strictly inside the actor's `observed_spans`.
- `advisory_idle_claimed.intervals` (`Array<{ seat: string, from: string, to: string, classification: string }>`):
  - `classification`:
    - `"unparked_container_hold"`: Drawn as a hatched overlay strip (`url(#container-hatch)`).
    - `"true_leaf_stall"`: Drawn as an amber overlay strip (`#fbbf24`).
- `context_compactions.events` (`Array<{ seat: string, ts: string, pre_drop_context_tokens: number, post_drop_context_tokens: number }>`):
  - Drawn as vertical pink markers (`#fb7185`) across the actor's lane. Tooltip displays: `Recorded context drop: <pre> → <post> tokens`.

#### Concurrency Histogram (`fleet_concurrency.histogram`)
Bar chart showing aggregate seconds spent at *k* concurrent active actors:
```json
"fleet_concurrency": {
  "effective_parallelism": 3.42,
  "histogram": [
    { "active_seats": 0, "secs": 3600 },
    { "active_seats": 1, "secs": 7200 },
    { "active_seats": 2, "secs": 14400 },
    { "active_seats": 3, "secs": 25200 },
    { "active_seats": 4, "secs": 21600 },
    { "active_seats": 5, "secs": 10800 },
    { "active_seats": 6, "secs": 3600 }
  ]
}
```

### 3.2. Tab 2: Work Lineage & Model Accounting (`#flow`)

#### Work Handoff Flow (`handoff_members` or `handoff_edges`)
Rendered as an interactive SVG Sankey diagram in `#sankey`:
```json
"handoff_members": [
  { "from": "arch-planner@core-rig", "to": "builder-backend@core-rig", "is_return": false },
  { "from": "qa-verifier@core-rig", "to": "builder-backend@core-rig", "is_return": true }
]
```
- Ribbons represent queue deliveries from sender to receiver.
- Width scales with handoff count.
- Deliveries with `is_return: true` (or `return: true`) render with amber dashed animated drift (`path.return`), signifying rework cycles.
- Activating a ribbon displays the exact delivery and return count in `#flow-detail`.

#### Model Token Accounting (`token_categories`)
Horizontal proportion bar in `#tokens`:
```json
"token_categories": {
  "input_uncached": 62450000,
  "cache_read": 348120400,
  "cache_write": 44180000,
  "output": 28160000
}
```

#### Attributed Token Buckets (`task_intake_overhead`)
Horizontal proportion bar in `#attribution`:
```json
"task_intake_overhead": {
  "assigned_mission_tokens": 396420000,
  "task_intake_overhead": 54180000,
  "ambiguous_tokens": 21850000,
  "unlinked_session": 10460400
}
```

#### Pair Friction Heatmap (`#heatmap`) & Median Table (`pair_medians`)
The heatmap supports five selectable metrics via `#heatMetric`:
1. `count`: Handoff volume between actors (from `m2_pairs.handoffs` or edge count).
2. `rate`: Return rate percentage (from `m2_pairs.return_rate * 100`).
3. `wait`: Median queue wait time in seconds (from `pair_medians.wait_median`).
4. `exec`: Median execution time in seconds (from `pair_medians.exec_median`).
5. `boundary`: Count of boundary crossings (from `ring_boundaries.edges.boundary`).

```json
"pair_medians": [
  {
    "from": "builder-backend@core-rig",
    "to": "qa-verifier@core-rig",
    "wait_median": 110,
    "wait_samples": 5,
    "exec_median": 480,
    "exec_samples": 5
  }
],
"m2_pairs": [
  {
    "from": "builder-backend@core-rig",
    "to": "qa-verifier@core-rig",
    "handoffs": 5,
    "return_rate": 0.2857
  }
],
"ring_boundaries": {
  "edges": [
    { "from": "builder-backend@core-rig", "to": "qa-verifier@core-rig", "boundary": "in_ring" },
    { "from": "sec-reviewer@core-rig", "to": "release-steward@gateway-rig", "boundary": "cross_rig_seam" },
    { "from": "release-steward@gateway-rig", "to": "arch-planner@core-rig", "boundary": "supervisory_plane" }
  ]
}
```
- Boundary types are constrained to: `"in_ring"`, `"cross_rig_seam"`, and `"supervisory_plane"`.

### 3.3. Tab 3: Actor Evidence Inspector (`#trace`)

Selecting an actor alias (`Actor 1..N`) from the dropdown `#seat` inspects that actor's operational summary:
- **Productive Yield (`m1_by_seat`)**:
  ```json
  {
    "seat": "builder-backend@core-rig",
    "tokens": 164820000,
    "closed_items": 38,
    "nonreturn_deliveries": 32,
    "tokens_per_closed_item": 4337368.42
  }
  ```
- **Tool Call Breakdown**: Displays `engineering_calls` (coding/testing actions) vs. `ceremony_calls` (status, sync, heartbeat checks) from `activity`.
- **Stall & Hold Attribution**: Displays `unparked_container_secs` and `leaf_stall_secs` from `activity`.

### 3.4. Tab 4: Layer Insights & Security Posture (`#insights`)

#### Compiled Insights (`insights`)
Standardized `insight_v1` result cards rendered in `#insight-list`:
```json
{
  "id": "I08",
  "name": "harness.action_failure",
  "version": "1.0.0",
  "domain": "harness",
  "status": {
    "state": "computed"
  },
  "population": {
    "what": "tool_facts",
    "n": 2526
  },
  "measures": [
    { "id": "I08.failed", "name": "failed", "value": 84, "unit": "actions" },
    { "id": "I08.settled", "name": "settled", "value": 2420, "unit": "actions" },
    { "id": "I08.unsettled", "name": "unsettled", "value": 22, "unit": "actions" },
    { "id": "I08.failure_rate", "name": "failure_rate", "value": 0.0347, "unit": "ratio" }
  ]
}
```

##### Admitted Insight Identifiers (`ALLOWED_INSIGHT_IDS`)
`I01` through `I25` (e.g. `I01`, `I02`, ..., `I25`).

##### Admitted Insight Names (`ALLOWED_INSIGHT_NAMES`)
- **Model Layer**: `model.invocations` (I01), `model.tokens.direct` (I02), `model.tokens.inclusive` (I03), `model.cost` (I04), `model.configuration_divergence` (I05), `model.counterfactual_routing` (I25).
- **Harness Layer**: `harness.capability_funnel` (I06), `harness.context_pressure` (I07), `harness.action_failure` (I08), `harness.trajectory_vortex` (I22), `harness.schema_drift` (I23).
- **Coordination & Lineage Layer**: `work.lineage_shape` (I09), `work.duration` (I10), `work.shared_allocation` (I11), `coord.queue_wait` (I12), `outcome.acceptance` (I19), `outcome.resource_efficiency` (I20), `comparison.descriptive` (I21).
- **Environment Layer**: `environment.placement` (I13), `environment.resources` (I14), `environment.effects` (I15), `coverage.source` (I18).
- **Security Layer**: `security.isolation` (I16), `security.authority` (I17), `security.authority_blast_radius` (I24).

##### Admitted Domains (`ALLOWED_DOMAINS`)
`"model"`, `"harness"`, `"coordination"`, `"environment"`, `"security"`.

##### Admitted Statuses & Reasons
- `state`: `"ok"`, `"partial"`, `"refused"`, `"not_applicable"`, `"insufficient_evidence"`, `"computed"`, `"unknown"`.
- `reason`: Closed set including `"empty population"`, `"source coverage is partial"`, `"unresolved parent session"`, `"estimated usd unknown"`, `"insufficient_sample"`, `"threshold_exceeded"`. Unrecognized strings are automatically stripped.

##### Summary Panels (`#lineage` & `#environment`)
- `#lineage` automatically binds to `payload.lineage` or insight `I09` (`work.lineage_shape`).
- `#environment` automatically binds to `payload.environment` or insight `I14` (`environment.resources`).

#### Security Posture (`security`)
Rendered in `#security`. The explorer strictly admits only closed-vocabulary kind and value pairs:

```json
"security": {
  "status": {
    "state": "computed"
  },
  "population": {
    "what": "security_facts",
    "n": 64
  },
  "counts": [
    { "kind": "permission_mode", "value": "acceptEdits", "n": 38 },
    { "kind": "permission_mode", "value": "default", "n": 26 },
    { "kind": "permission_decision", "value": "allow", "n": 58 },
    { "kind": "permission_decision", "value": "deny", "n": 6 },
    { "kind": "sandbox_policy", "value": "workspace-write", "n": 48 },
    { "kind": "sandbox_policy", "value": "read-only", "n": 16 },
    { "kind": "approval_policy", "value": "on-request", "n": 42 },
    { "kind": "approval_policy", "value": "never", "n": 22 },
    { "kind": "permission_profile", "value": "other", "n": 14 },
    { "kind": "approved_prefix_count", "value": "42", "n": 42 },
    { "kind": "sandbox_override_requested", "value": "true", "n": 3 },
    { "kind": "dangerous_command", "value": "pipe_to_shell", "n": 2 },
    { "kind": "dangerous_command", "value": "force_push_with_lease", "n": 1 }
  ]
}
```

##### Closed `SECURITY_ADMISSION` Vocabulary Rules
| Kind | Admitted Values |
|---|---|
| `permission_mode` | `"default"`, `"auto"`, `"acceptEdits"`, `"plan"`, `"bypassPermissions"`, `"other"` |
| `permission_decision` | `"allow"`, `"deny"`, `"other"` |
| `sandbox_policy` | `"danger-full-access"`, `"read-only"`, `"workspace-write"`, `"true"`, `"false"`, `"other"` |
| `approval_policy` | `"never"`, `"on-request"`, `"other"` |
| `permission_profile` | `"other"` |
| `sandbox_override_requested` | `"true"` |
| `dangerous_command` | `"recursive_delete"`, `"pipe_to_shell"`, `"force_push"`, `"force_push_with_lease"`, `"chmod_world_writable"`, `"sudo"`, `"disk_write_device"`, `"credential_file_access"`, `"network_exfil_pattern"` |
| `approved_prefix_count` | Exact numeric digits string (`/^\d{1,18}$/`, e.g. `"42"`) |

Any kind or value outside this closed matrix is immediately sanitized to `"redacted"` and discarded.

## 4. Privacy & Client-Side Projection Invariants

The Offline Fleet Explorer implements four strict client-side projection invariants in `site/viewer.html`:

1. **Deterministic Actor Aliasing (`Actor 1..N`)**:
   Raw seat and actor identifiers (such as `arch-planner@core-rig`, internal hostnames, or usernames) are dynamically mapped to local sequential labels (`Actor 1`, `Actor 2`, etc.) upon projection. The raw strings are never rendered into HTML, SVG, or DOM attributes.

2. **Total Text Stripping & Closed Vocabularies**:
   The explorer accepts *zero arbitrary text fields*. Free-form commit messages, code diffs, command strings, prompts, file paths, and transcript excerpts are discarded. Only validated numeric values and closed-vocabulary tokens (`ALLOWED_INSIGHT_IDS`, `ALLOWED_INSIGHT_NAMES`, `ALLOWED_MEASURE_KEYS`, `SECURITY_ADMISSION`) pass the intake filter.

3. **Life Boundaries & Unobserved Spans**:
   Activity states (`running`, `idle`, `needs_input`) are strictly scoped within recorded `observed_spans`. When an actor's container or session is unmounted, the timeline leaves the interval unobserved (slate background). Running states never bleed or interpolate across gaps.

4. **Zero-Persistence & In-Memory Execution**:
   Export files are parsed via `FileReader.readAsText()` directly into JavaScript objects in memory. No data is stored in `localStorage`, `IndexedDB`, or cookies, and no network requests are dispatched.
