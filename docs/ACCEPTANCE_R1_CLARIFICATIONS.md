| K11 | 2026-10-11 20:05 | Tool-loop window in a long failure run (F6) | A **run** is a sequence of consecutive failures of the same tool with the same trimmed input, by the same seat, in one session (harness, session; rule 1). Only an unknown result or any other tool call in that session breaks it (rules 3–4). The run is a loop if **any** 3 consecutive failures in it span at most 600 s from their 1st to their 3rd failure, inclusive (exactly 600 s counts; rule 5). The window slides; it is not anchored to the run's first failure. Rule 5's "1ª à 3ª falha" names the 1st and 3rd of the qualifying three. Earlier, slower failures never erase a qualifying three. **Episode:** the whole run is one episode, with count = the full run length, including failures before or after the qualifying three. It is never split into overlapping loops (rule 6). A run with no qualifying three is not a loop. **Missing timestamp:** a failure without a timestamp stays in the run and in the count, but a three whose 1st or 3rd failure has no timestamp cannot qualify; no time is guessed. **Fixtures** (failure times in seconds from t0, one run): 0, 400, 700, 800 → one episode, count 4 (2nd–4th span 400 s; 1st–3rd span 700 s); 0, 400, 700, 1101 → no loop (spans 700 s and 701 s).
