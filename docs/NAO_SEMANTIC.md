# Local semantic queries and Nao

Dendro materializes eight scoped projections rather than maintaining a second set of metric formulas. Four v0.8.0 domain projections (`v_message_mix`, `v_subagent_lineage`, `v_security_posture`, `v_process_resources`) summarize message, lineage, security, and process facts. Four OpenRig-compatibility projections (`v_seat_idle_ranking`, `v_handoff_rework_analysis`, `v_mission_token_burn`, `v_executive_governance`) are scoped views of **one canonical decisions report**. All eight query derived tables in the owned analytics database. Fact schemas and source logs remain unchanged.

Run `dendro materialize --db <database> --from <RFC3339> --to <RFC3339> [--rig <rig>]` after ingestion. Windows are canonical half-open windows; rig scope follows canonical session bindings. Only one scope is materialized at a time. Refresh runs with a 4GB DuckDB memory cap and one query thread. Canonical arrays are projected in Rust into typed tables with appenders/prepared statements; SQL never expands the full parent JSON through lateral table functions. Refresh is transactional, records its cutoff and formula version, and replaces the previous scope. The canonical read-only report connection closes before the derived write transaction. Full row-content signatures across all canonical tables fence concurrent updates. Every supported AnalyticsStore canonical writer marks derived cache state dirty in the same write transaction, including mutable model/category/lineage metadata. Public views use this cheap marker to refuse stale answers; do not query private cache tables directly. Local ask also performs a full content-signature preflight. Direct external SQL writes bypass supported writer invalidation and require refresh/preflight before Nao use; the views do not promise protection against arbitrary database tampering. A historical snapshot describes its stated window, never an implicit rolling “today”.

SQL fields use canonical units: seconds for seat bands, milliseconds for pair wait/turnaround, fractions for return/ceremony ratios. `m1` retains canonical closed-item denominator availability. A null ratio, missing row or `no data` is not a measured zero. Pair values are the canonical handoff-friction pair projection; productive and recovery transfers retain its definitions. Vortex witnesses overlap and cannot be summed as independent work. The executive projection retains canonical metric fields including recovery subtypes, concurrency, compaction, cache bleed and four-eyes evidence. Its row_json retains the full canonical payload for exact parity and trace drill-down.

Mission rows group four token components by seat/model/effort, attribution bucket, and **arrays** of missions/issues/phases from canonical lineage. They preserve ambiguous, intake-overhead and unlinked buckets. Canonical tagged-lineage records omit unlinked/collision usage; those records stay present with the existing canonical session-binding classification and explicitly unavailable tagged lineage. Do not independently unnest dimensions and sum afterward; this multiplies records. `dendro_semantic_usage` has exactly one row per canonical scoped usage key; `dendro_semantic_provenance` is the report source-key census. The canonical CLI trace (`--metric-id`, identical scope) provides deeper source locators and reproducibility limits. Reasoning remains included in output and must never be added again.

`dendro init-nao --db <database> --output <new-directory>` writes a new workspace and refuses existing destinations, traversal and symlink ancestors. It writes the actual canonical database path into native `nao_config.yaml`, a native `RULES.md` and `semantics/dendro.md`, plus the Dendro column manifest. Configuration was checked against [getnao/nao cdb448c](https://github.com/getnao/nao/tree/cdb448c686150eb5aebf3a2b6a31a49a7c6c23ac/cli/nao_core/config): `NaoConfig` and `DuckDBConfig` accept project_name/databases/type/path, table include patterns and allow_listed_only. Upstream local DuckDB opens read-only and disables external access. No LLM provider or credentials are provisioned. Nao's own client is optional; this change does not claim a deployed Nao UI or a live provider roundtrip.

The deterministic local `dendro ask` adapter supports six bounded English patterns (Compare, Rank, Explain, Verify, Trace and HonestLimits). In `v0.6.0`, `dendro ask` accepts a positional question (`dendro ask "<question>"`) as well as `--question`, supports `--list-intents` (or bare `dendro ask` with no question) to print all 6 canonical intents and example phrases without requiring a database, and automatically refreshes the 4 canonical OpenRig-compatibility views (`v_seat_idle_ranking`, `v_handoff_rework_analysis`, `v_mission_token_burn`, `v_executive_governance`) when `dendro_semantic_snapshot` is missing or stale (unless `--no-refresh` is set), recording `"auto_materialized": true` and `"window_resolution"` in the JSON response. The same materializer installs the four v0.8.0 domain views. Those views are all-time counts (the snapshot window labels rows and does not filter them) and are not targets of the six English intents. CPU and cost stay on insights `I14` and `I04`; the views do not recompute them. Both `dendro materialize` and `dendro ask` accept `--window 1h|24h|7d|30d|all` (anchored to rig-scoped recorded bounds when `--from`/`--to` are omitted). Unknown metrics and management commands refuse. Comparison requires an explicit canonical baseline, explicit scope and matching formula, and observed usage in both periods. The matcher accepts whole documented phrases (including natural `v0.6.0` aliases such as `"highest idle"`, `"where is time being wasted?"`, `"worst yield"`, `"token burn"`, `"where do tokens go?"`, `"rework"`, `"handoff friction"`, `"verify"`, `"trace idle"`, `"trace tokens"`, `"trace handoffs"`, and `"known limits"`) and normalizes case, whitespace and terminal question marks. Appended relative-date, mission, seat, harness or rig qualifiers refuse with the selected snapshot scope; they are never silently ignored. Select exact scope via `--window` / `--from` / `--to` / `--rig` and supply a canonical baseline explicitly. Rank supports idle seconds and worst token burn per closed item; absent denominators remain unavailable. Explain presents observed rework evidence and refuses absent observations. Neither Explain nor before/after comparison claims causal proof. Supplied percentages in Trace are questions, never accepted facts. `templates/nao/prompts.md` holds examples and limits. The Rust adapter enforces these restrictions; an independently configured external LLM is not a deterministic safety boundary.

## Eight scoped projections and dashboard templates (`v0.8.0`)

`templates/nao/semantic_models.yaml` registers all eight projections. `templates/nao/dashboards/` holds one YAML dashboard template per projection. The four compatibility templates remain so existing Nao workspaces keep their ids. The four domain templates are additive.

### Domain projections

These views are counts, max, and group-by only. `window_from` / `window_to` label the snapshot. They do not filter rows. A missing lazy fact table yields an empty projection, not a measured zero.

| Projection | Dashboard template | Id | Title | Query |
| --- | --- | --- | --- | --- |
| `v_message_mix` | `templates/nao/dashboards/message_mix.yaml` | `message_mix` | Model & Harness Message Mix | `SELECT * FROM v_message_mix ORDER BY message_count DESC, harness, native_session` |
| `v_subagent_lineage` | `templates/nao/dashboards/subagent_lineage.yaml` | `subagent_lineage` | Sub-Agent & Work Lineage Graph | `SELECT * FROM v_subagent_lineage ORDER BY child_count DESC, harness, parent_session` |
| `v_security_posture` | `templates/nao/dashboards/security_posture.yaml` | `security_posture` | Security & Authority Posture | `SELECT * FROM v_security_posture ORDER BY observation_count DESC, harness, kind` |
| `v_process_resources` | `templates/nao/dashboards/process_resources.yaml` | `process_resources` | Environment & Process Resources | `SELECT * FROM v_process_resources ORDER BY max_rss_bytes DESC, harness, root_key` |

`v_message_mix` counts `message_facts` by harness, native session, role, direction, and modality. It never projects message text. Token components stay on `I02` `model.tokens.direct`. Settled tool failure stays on `I08` `harness.action_failure`.

`v_subagent_lineage` counts explicit `session_edges` per parent session: child count, edge count, and status counts. Depth, cycles, diamonds, and unresolved parents stay on `I09` `work.lineage_shape`. Unresolved parents are counted and are not invented as roots.

`v_security_posture` counts `security_facts` by harness, kind, and closed value. Admitted kinds are `permission_mode`, `permission_decision`, `sandbox_policy`, `approval_policy`, `permission_profile`, `approved_prefix_count`, `sandbox_override_requested`, and `dangerous_command`, each with its own value list (`other` when the source is outside the list, or a digit count for approved prefixes). Presentation groups those kinds as policy, grant, approval, attempt, effective authority, and effect. A grant is an observation. It is not an effective-authority verdict, and command text is never stored.

`v_process_resources` counts processes and samples per `root_key` and harness and exposes `max_rss_bytes` per `rss_unit`. `I14` `environment.resources` is CPU deltas and max sampled RSS. Source read, projected, unprojected, and refused counts stay on `I18` `coverage.source`. RSS units are never mixed in SQL. Attribution on this view is process attribution (launched versus discovered), not an isolation stage.

The operator pages that read these templates use domain headings (model token and cost accounting, work handoff friction, actor activity and session yield, governance and verification) and badge seat, rig, and four-eyes columns as OpenRig adapter bindings.

## Two-tier intent routing (`v0.7.0`)

`dendro ask` does not generate SQL from the question. Routing has two tiers, then a suggestion list when both miss.

1. **Exact phrase.** The question is trimmed, a trailing `?` or `.` is removed, internal whitespace is collapsed, and the result is lowercased. That string must equal one supported phrase (`highest idle`, `where do tokens go`, `explain handoffs`, `what changed`, `trace tokens`, `honest limits`, the `where does <0-100>% idle come from` pattern, and the other phrases in `supported_intents`).
2. **Token scoring.** If the exact phrase misses, the question is split into alphanumeric tokens. A fixed unsupported-qualifier list refuses the question before any score is accepted: mission or calendar words (`mission`, `week`, `yesterday`, `since`, …), SQL or mutation words (`select`, `drop`, `delete`, …), forecast or money words (`forecast`, `roi`, `savings`, …), secret words, and any token containing `@`. Remaining tokens route only when they hit the required groups for one intent. Rank needs a ranking word and an idle, yield, or token word. Explain needs an explain/why word and a rework or handoff word. Compare, verify, trace, and honest-limits use the same kind of group test. This is token overlap with the supported vocabulary, not an edit-distance match and not a free-form paraphrase.

A miss returns `supported_examples` from `suggest_closest_intents`: each catalog intent is ranked by how many question tokens of length 3 or more appear in its JSON text. The text answer prints up to three of those suggestions. The cockpit `:` drawer uses the same ranking for autocomplete.

`--format text` prints `human_ask_answer`. `--format json` prints the response document. When `--format` is omitted, a terminal receives text and any other stdout receives json, so scripts can keep parsing one JSON object. `--list-intents`, and `dendro ask` with no question, print the JSON catalog and do not open the database. `--no-refresh` still refuses a stale snapshot instead of writing the semantic cache. Auto-materialize on the CLI path is unchanged from `v0.6.0`.

Nao Option B is the provisional sponsor-selected primary conversational surface. This is delegated product authority, not an invented organic operator validation. The cockpit is a separate diagnostic interface; its `:` drawer calls this same adapter and does not add a second metric language.

Run `cargo test -p dendro-core --test semantic --test benchmark_nao -- --nocapture`. The benchmark loads 5,500 real canonical usage facts plus identities, activity, tools and queue facts, uses the production report/materializer/views, checks token/second conservation and source keys, warms each view, consumes all result rows, then reports measured mean and maximum across 20 iterations. Nonfatal per-view targets are 15/10/10/5ms. Cold preparation and first execution are reported separately. Report generation and explicit refresh are outside the interactive query measurement; they are not claimed to run under 20ms.

### Performance policy amendment (2026-10-23)

The user approved classifying the 20ms target as directional, not a release acceptance criterion. Its suitability as an operator requirement has not been validated. Retain measured mean and maximum timings as performance evidence: the controlled run's maximum of 20.339ms exceeded the historical 20ms criterion, and an incidental full-suite pass does not supersede that observation. This amendment does not turn the historical result into a pass or establish a validated SLA.

The user subsequently authorized implementing this policy in `canonical_semantic_views_latency_and_conservation` in `crates/dendro-core/tests/benchmark_nao.rs`. This gate amendment supersedes only that benchmark's historical mean/maximum assertions below 20ms: the test now reports measured timings and nonfatal directional-target outcomes for both mean and maximum, explicitly marking latency as outside acceptance. The 20 warm iterations, full row consumption, cold/first-run diagnostics and nonfatal 15/10/10/5ms per-view targets remain. All correctness checks, including conservation, source keys and schema checks in the semantic suite, remain required. Other benchmark gates, frozen oracles and historical review/results are unchanged; their historical criteria do not define current acceptance for this amended benchmark. Independent storage-consumer finding F1 remains a correctness blocker; this amendment grants no storage acceptance or release authority.

For refresh stage timings without payload logging, set `DENDRO_TRACE_SEMANTIC=1`. A regression test materializes 5,500 canonical facts plus a 16MB report extension under a 512MB cap; unrelated report extensions must not multiply memory by the number of usage rows.
