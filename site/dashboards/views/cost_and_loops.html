Model Token & Cost Accounting (I02 / I04)

Disjoint token components per model, plus observed and estimated cost kept apart. Reasoning stays inside output. Unknown cost is not zero. Task, actor, and model token accounting across invocations.

Model Layer Tracks physical 4-component token burn (uncached input, cache read, cache write, output) and prompt cache hit efficiency per model and actor without currency guesswork.

4-Component Token Distribution by Model: Each stacked bar decomposes token consumption into physical token classes:

Uncached Input (Cyan)

Fresh prompt tokens processed from scratch by the model API. High proportions indicate poor prompt cache reuse.

Cache Read (Emerald)

Prefix tokens served from existing prompt cache. High cache hit rates dramatically reduce billing and turn response times.

Cache Write (Purple)

New tokens written to context checkpoint store to establish prefix caching for future turns.

Generated Output (Amber)

Model output tokens, including tool calls and internal reasoning tokens (per I02 disjoint standards).
