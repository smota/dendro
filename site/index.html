Why care

Activity is easy to fake. Flow is what ships software.

When you run coding agents across multiple terminals, worktrees, or team roles, you get megabytes of raw logs and very little clarity on what actually moved the work forward.

Without Dendro · The Illusion of Busyness

Terminals scroll fast while work quietly stalls

  • Hidden handoff bottlenecks: An agent finishes a task and sits idle for 45 minutes waiting for a review or human prompt, looking identical to a completed job.
  • Ping-pong rework loops: Two roles pass the same task back and forth four times, burning token budget and context windows without converging.
  • Unattributed spend: Cloud invoices show total token spend, but never which workflow, model choice, or context reset drove the cost.
With Dendro · Retrospective Clarity

Every session read like the rings of a tree

  • Five disjoint seat activity bands: Observed session intervals are separated into five disjoint activity bands with unknown intervals explicitly retained: active work, waiting on a human, waiting on a peer handoff, stalled with work in queue, or cleanly parked.
  • First-pass vs. rework visibility: See immediately which tasks delivered cleanly on the first pass and where handoffs bounced backward.
  • Local, private, zero-setup: Point Dendro at the session logs already on your disk. Nothing leaves your machine.
What it brings to the table

Three ideas that replace guesswork with evidence.

Dendro is built for engineering leaders, platform architects, and developers who want honest operational feedback rather than AI hype.

01 Busy vs. Productive

Account for every second of the workflow

Instead of counting raw turns or lines of code, Dendro reconstructs the true timeline of every actor—separating active model and tool work from human wait times, peer handoff delays, and stalled queues.

02 The Cost of Rework

Spot ping-pong loops and context resets

When an agent's context window fills up and compacts, or when a reviewer rejects a change three times in a row, costs spike. Dendro highlights exactly where context drops and rework loops happen.

03 Honest Boundaries

Only what local evidence can prove

Dendro never invents "developer hours saved" or subjective code-quality scores. Every chart—in the terminal cockpit, the offline browser explorer, or plain-English queries—is backed by local log facts.

60-Second CLI & Connected Studio Quickstart

From a local checkout with Rust installed, build and open the connected studio. Build time depends on your machine; “60 seconds” describes the command path.

cargo build --release --locked
./target/release/dendro status
./target/release/dendro dashboard --serve 127.0.0.1:4242 --site-dir ./site

Open http://127.0.0.1:4242. Ctrl-C stops the server.

Four architectural layers

Model, Harness, Coordination, Environment

  • Model. Invocations, tokens, cache, pinned cost, and a routing simulation that does not touch the router.
  • Harness. Tool families, action loops, trajectory shape, and envelope drift across Claude Code, Codex, AGY, Grok, Pi, and OpenRig.
  • Coordination. Handoffs, queue wait, lineage, and acceptance. Busy time stays split from flow.
  • Environment & Security. Placement, CPU and RSS, grants, and evidenced reachability. Exposure is not inherited authority.
Five-layer capability studio

What the fleet actually ran

  • Tool families. Shell/Exec, Read/Inspect, Edit/Patch, Search/Grep, Subagent Spawn, MCP Call, Skill Load, Web/Fetch, Task/Queue, Governance/Gate.
  • Primitives. The built-in verbs under those families.
  • Skills. Declared versus invoked. The funnel is I06.
  • MCP. Server call counts, never payloads.
  • Hooks. Lifecycle guardrail events, counted, not quoted.
Active intelligence · I22–I25

Four consoles with the limit printed on the glass.

Each console discloses one of two resolution modes: materialized Schema 5 reference views (Mode A) or labeled live windowed fact-table heuristic fallbacks (Mode B). I01–I21 stay on the hub strip beside them.

I22 Harness · Trajectory Vortex

Inspect trajectory loops in either mode

Mode A: v_trajectory_vortex computes exact 32-dim FLOAT[32] array_cosine_distance. Mode B: turn-length variance and self-transition proxy, clamped to 0.08..0.82; trips at >= 25 turns and >= 0.55 self-transition. Not an embedding cosine measurement. A trip is not a cause.

I23 Harness · Schema Drift

Read the DNA of every harness envelope

Mode A: v_schema_drift measures VARIANT envelope L1 structural drift across harness versions. Mode B: daily metadata cohort buckets from message_facts, with an L1 proxy clamped at 0.45 and keys_retyped = 0. Drift is not a compatibility verdict.

I24 Environment · Blast Radius

Follow recorded session reachability

Mode A: v_authority_blast_radius uses 8-hop duckpgq evidenced-only session reachability. Mode B: a recursive CTE (depth < 4) over recorded session_edges plus security_facts authority-check scopes. Dependency exposure does not grant authority.

I25 Model · Counterfactual Routing

Simulate the inflection. Leave the router alone.

Mode A: v_counterfactual_routing performs pinned-tier simulation and refuses when no pricing tier is pinned. Mode B: heuristic observed * 0.75 simulated fast-tier envelope total (0.75 × observed, leaving a 25% counterfactual gap) in normalized token units against an assumed 128k context threshold. This is a counterfactual simulation proxy, never a measured financial saving or a live routing change.

Mode B — Live Windowed Fact-Table Fallbacks: intelligence_fallback in connected_web.rs derives labeled heuristic proxies from tool_facts, usage_facts, message_facts, and session_edges for arbitrary live time windows (?window=7d, YYYY-MM-DD..YYYY-MM-DD) or empty/unmaterialized Schema 5 tables. The live I22–I25 screenshots showcase Mode B over the active workspace's live fact tables, with SIMULATED TIER TOTAL (COUNTERFACTUAL) representing the simulated fast-tier envelope total (0.75 × observed, leaving a 25% counterfactual gap) in normalized token units. These proxies are distinct from Mode A — Materialized Schema 5 Reference Views.
